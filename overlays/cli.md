# Overlay: cli

- The owning module is the CLI application. Keep argument parsing, terminal presentation, workflow orchestration, domain logic, and external effects separate; internal packages are not automatically new independently owned modules. Follow the repository's existing language, package, and test conventions.
- Test observable behavior at the command boundary: arguments and stdin in; exit status, stdout/stderr, and persisted results out. Cover successful commands, invalid inputs, failures, and interruption. Preserve documented commands, aliases, flags, defaults, output formats, and state locations unless a change is explicitly approved.
- Keep parser-specific objects at command adapters. Workflows take explicit typed inputs; filesystem, subprocess, network, clock, and interactive prompts have injectable boundaries where useful. Test domain logic directly without patching re-exported implementation details. Avoid generic frameworks or plugin systems unless required.
- Verify entrypoints in subprocesses from an unrelated working directory. Where supported, help and shell completion must work without optional execution dependencies, credentials, networking, or state writes. Test installation and completion using temporary HOME, PATH, and state directories; never edit the operator's real shell startup files in tests.
- Use synthetic datasets and isolated temporary state. Mock remote services, paid inference, package managers, and destructive subprocesses. Obtain explicit approval before live billable calls, publishing messages, modifying real datasets, or installing system packages. Prefer dry-run when available. Never expose secrets or sensitive payloads in evidence.
- Preserve preflight checks, billing confirmations, locking, atomic writes, reset/overwrite protections, and cancellation diagnostics. Local cancellation must not imply that remote work stopped. Contract or installation-path changes need explicit alignment; document reinstall or compatibility requirements rather than silently choosing them.
- Keep concurrency, queues, in-memory accumulation, retries, and output bounded. Preserve existing limits during refactors; new retry behavior needs finite attempts and backoff. When scale targets matter, verify them with a targeted test or measurement.
- Run formatting, type/lint checks, and tests for the affected CLI using the repository's managed environment and the checks command from dt.mjs info. Capture command, exit status, and relevant output; report skips and mocked boundaries honestly.
- For a local browser review UI, also apply the web overlay: verify the critical path with synthetic data and capture browser evidence where possible. Human verification owns visual/layout acceptance; an offline test suite is not evidence of live-service behavior.
- This overlay defines verification, not tier selection. Apply the workflow's gates and escalation rules; any approved exception must be explicit.
